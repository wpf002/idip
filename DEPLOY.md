# Deploying the IDIP backend (Render)

This repo ships a [`render.yaml`](render.yaml) Blueprint that provisions the
FastAPI backend (Docker) plus a managed Postgres database, and serves the API
over a fixed `https` URL — no dependency on your Mac or the local network.

## One-time deploy

1. Create a free account at **https://render.com** and connect your GitHub
   (authorize the `wpf002/idip` repo).
2. Render dashboard → **New** → **Blueprint** → select the `idip` repo.
   Render reads `render.yaml` and shows the plan: a web service `idip-backend`
   + a Postgres database `idip-db`.
3. Click **Apply**. First build takes a few minutes (Docker image + DB).
4. When it's live, the service has a URL like
   **`https://idip-backend.onrender.com`**. Open `/health` to confirm:
   `{"status":"ok",...}`.

Secrets (`SECRET_KEY`, `HMAC_SECRET`) are auto-generated by Render and persist
across restarts. `DATABASE_URL` is wired from the managed Postgres
automatically (the app rewrites the scheme to `postgresql+asyncpg://`).

## Point the app at it

Once you have the URL, create a venue to get its API key, then update the app:

```bash
curl -X POST https://idip-backend.onrender.com/admin/location \
  -H 'Content-Type: application/json' \
  -d '{"name":"My Venue","state_code":"TX"}'
# -> returns {"id":..., "api_key":"idip_..."}
```

Put the URL + key in [`mobile/src/config.ts`](mobile/src/config.ts) and rebuild
the app. After that the phone talks to the cloud backend over HTTPS on any
network (Wi-Fi or cellular) — the local-IP / same-Wi-Fi requirement is gone.

## Notes & limits (free tier)

- The free web service **spins down after ~15 min idle**; the next request has
  a cold start of ~30–60s. Fine for testing; upgrade to a paid instance for
  production (always-on).
- The free Postgres has a storage cap and **expires after ~30 days** — move to
  a paid database before relying on it.
- `autoDeploy: true` means every push to `main` redeploys automatically.
